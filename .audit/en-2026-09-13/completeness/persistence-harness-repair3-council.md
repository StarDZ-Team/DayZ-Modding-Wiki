### PR3-B01 — Directory creation and snapshot routes cannot execute

**Blocker; controller:27,34,53,56,59,75.** `New-Item` has no `-LiteralPath` parameter in PowerShell 7.6.0. Every `New-Dir` therefore fails; the initially absent approved root has the same error. Reviewer `new-directory-supported-parameter` reproduces the exact parameter-binding error without launching anything. After that repair, the snapshot and clone destinations still have nonexistent immediate parents (`baseline-v1`, `verify-v1`, `upgrade-chain`, `pre-bad`, `bad-a`, `bad-b`), while `New-Dir` requires that parent to exist. `copy-fresh-nested-snapshot-parent` reproduces this independently, before directory creation. Create/check each ordinary parent within the approved root, preserve literal-path copy semantics, and test every real destination route. Preparation also calls `Get-Date -Format'yyyyMMdd-HHmmss'` without an argument separator (line 53); `prepare-date-format-argument` reproduces its Date conversion error. These failures currently happen before attempt receipts/finally.

### PR3-B02 — Seed, migration, and nondefault SAVE oracles contradict the emitted protocol

**Blocker; controller:43,45–47,49,65; fixture v2:117; mission init-v2.c:86–95.** Seed `Load-State` returns immediately and no caller ever invokes `Oracle` with `seed-v1`; a fresh suite cannot produce its required oracle. Even with a reviewer-created valid oracle, normal v1 saves throw because the omission query accesses absent `fields.locked` under StrictMode. Honest schema-1 v2 loads emit `migratedLocked=false`, but `Record` requires `locked`, so migration throws too. Finally `Save-State` excludes `set-true-v2` from the true-control cases: the intended true save fails, while the incorrect all-false save passes. Five named probes reproduce these paths. Consume the actual variant schemas, initialize/adopt each label only from validated evidence, and bind the sealed oracle/anchor to successful seed and same-v1 receipts; currently neither file has such receipt bindings and verify-v1 writes it before the run succeeds.

### PR3-B03 — Smoke/readiness and shutdown-state enforcement remains unsound

**High; controller:48,64–67; init-v1.c:27,51; init-v2.c:23,39; init-matrix.c:23,38; init-nomod.c:28,32.** All four templates print `SHUTDOWN_STATE` from an unconditional 240-second call-queue timer. That proves only timer execution after mission construction, not engine shutdown state or process-start-relative shutdown. The loop treats its substring as shutdown evidence. Smokes never require CE completion; `Smoke-State` accepts `ASSERT_FAIL` and reversed ready/shutdown order (reproduced). Missing ready/CE is not stopped at its cutoff; the loop can wait until T+420. A persistence trigger is written before the shutdown check, and only CE plus `Load-State` precedes it: native module/private-init/config/selected-storage/error checks happen after exit. Missing reload callbacks throw immediately on the first CE poll rather than remain pending through the bounded callback deadline. Event clock values are parsed but never compared with process start, trigger, cutoffs, or exit. Use genuine engine lifecycle evidence, an explicit bounded state transition gate, and current native module/private-init/storage witnesses before mutation. Exit code 0 and retained-process cleanup are improvements, but the synthetic timer must not certify scheduled self-exit.

### PR3-B04 — Events are correlated but not a strict typed protocol

**High; controller:38–39,43,46,48–49.** Wrong-run events are rejected before filtering, but field extraction skips arbitrary text, accepts unknown kinds/fields and a second `position`, and does not consume the whole record. Integer casts accept schema `1.1` as 1; PID regex accepts blocks outside signed-int range. `Phase-State` accepts a run with no `SPAWN_OK`/`ENUM_OK`/phase assertion/lifetime observations, unexpected mutation callbacks, and loads indexed after ready. All are reproduced. Bad-read `LOAD_FAIL` can even name variant v1 with an unrelated PID; only its label/schema/stage are checked. Define exact event kinds, fields/types/cardinality/order per phase, validate all events including mutation/counter/failure observations, and reject malformed tokens before selecting the expected set. The private-init check at line 66 is an arbitrary whole-RPT path substring, not an exact parsed native module record.

### PR3-B05 — SAVE observation policy rejects permitted observations and constrains native faulty fate

**High; controller:47; init-matrix.c:87–99.** `Set-Of` counts every SAVE in the run before checking its index, so harmless pre-ready saves plus a complete correct post-ready set fail (`SAVE count mismatch`). Pre-ready evidence must remain visible without satisfying the post-ready oracle. In a bad read the required save labels are only the two controls; a surviving faulty entity's ordinary SAVE is always rejected as an extra record, even though the mission explicitly permits it to remain. The reviewer reproduces that rejection. Preserve and classify the known faulty record's observations separately, require the two exact valid controls, and reject genuinely unknown/duplicate/conflicting callbacks without silently converting the accepted present-or-absent experiment into an absent-only save requirement. Actual native survival/save behavior remains unknown.

### PR3-B06 — Diagnostic allowlisting is not reviewed or consistently comparable

**High; controller:37,40–41,51,66.** The repaired parser correctly terminates the retained six-frame stack and detects enveloped standalone errors; changed stack lines and counts fail. However, unchanneled compile errors are omitted, severity/channel distinctions collapse, and unrestricted `message.Replace(profilePath, ...)` changes message content rather than only structured prefixes. Those gaps have probes. Baseline mode unconditionally promotes every observed diagnostic to an allowlist, including an injected fatal unknown-type diagnostic; no pre-reviewed list is consumed. The allowlist file is not bound to the no-mod receipt or immutable manifest. Four different private mission paths also make the same retained `CreateCustomMission()` stack differ across control/candidates; line padding does not normalize the path, and a synthetic common stack reproduces the mismatch. Reconcile this with the accepted narrow normalization/common mission contract, preserve exact source locations/messages/counts, and apply candidate attribution plus the approved error policy to every phase. Malformed-record native diagnostics need explicit observation policy; there is no separate handling in the current controller.

### PR3-B07 — The thirteen-process DAG can consume stale, failed, or changed inputs

**High; controller:17,52–56,60–66,69,75.** `Gate` validates a success wrapper/hash but never reads the referenced receipt's outcome/phase/suite fields or later failed attempts. Both a failed rerun behind an old success and a wrapper pointing at a failed unrelated receipt pass the probes. Smokes bypass `Gate` entirely, allowing candidate launch before the no-mod control. Immediate predecessors do not revalidate changed ancestor successes. Existing chain storage is recorded but never compared with the predecessor output, so an edited upgrade/bad branch can launch. `Open-Suite` records but does not rehash executable bytes/version before launch; the prepared dynamic CE/config values are labels, not checks of supplied inputs. Staged package equality is useful, but package source receipt lists are not checked for the exact current variant/member set. Enforce immutable, fully reopened successful predecessors, invalidate old authorizations on failed attempts, compare branch input to the exact parent output, bind/revalidate the executable and generated run config, and restrict differences to declared fields.

### PR3-B08 — Snapshot and final-closure receipts are not authoritative

**High; controller:34–35,45,56,75.** Initial freeze copies do not prove source-before/source-after/destination equality. Later clones compare `f.files`, but never verify `f.manifestHash` or `parentReceiptSha256` or bind the snapshot receipt itself to a success ledger; changing the snapshot plus its manifest goes undetected by this design. Neither snapshot's original identity is anchored elsewhere. Final closure checks two current snapshot lists and existence of the bad-a-read success file, then writes the literal `processCount=13`; it does not reopen all thirteen successful exact-input receipts or verify both independent clone identities. It only runs when bad-b-read is last, although the DAG also permits bad-a-read last. Anchor freezes to validated exited/released parents, retain both clone identities, and derive final completion from the full validated DAG in either legal branch order.

### PR3-B09 — Ownership, release, and failure receipts are incomplete

**High; controller:24–27,34,53–55,59–67,75.** Ancestor reparse checks and fail-closed single-file hardlink probes are meaningful repairs. But the lock uses check-then-`Set-Content`, not exclusive creation, and is acquired after context/storage/config/staging mutations. `owner.json` is never consulted or updated. Two dispatches can race; a failed attempt can overwrite an active lock. The fixed default port is reused, with no occupancy/release check, no process-handle disposal or file-release proof before clones. Preparation, `Storage`, staging, freeze/final-closure errors occur outside the attempt `try/finally`; even `Process.Refresh` in finally can abort receipt writing. Failed runs retain no log hashes (`logs` is assigned only on success), and successful receipts hash one RPT rather than the complete log set. External executable/PBO hardlink/ancestor status is not rechecked at consumption. Acquire exclusive ownership before mutations, validate consumed inputs physically, and make every dispatch/failure/cleanup path durably observable before it can authorize downstream work.
